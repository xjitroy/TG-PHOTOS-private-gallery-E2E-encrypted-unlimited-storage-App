# Current production readiness — 0.19.0

The implemented native Kotlin/Compose app has encrypted backup/recovery, normal Cloud and independent Private Vault, media playback/editing, folder-scoped filtering, exports and configurable encrypted temporary storage. This audit fixes concrete responsiveness, UI, clipboard and export ownership defects. Build/test evidence is reported separately; passing host checks is not a phone acceptance or independent cryptographic audit.

The owner has authorized comprehensive feasible verification and personal and public artifact delivery. No further generic verification permission is required. Actual production release remains blocked by:

1. **Android execution evidence.** Installed adb37.0.1 aborts before device enumeration because `/home/agent/.android` is read-only; a narrowly requested writable path does not change that mount. `/dev/kvm`, USB bus, emulator executable and system images are unavailable. No native screenshots/FPS/gesture/notification/provider/process-recreation/biometric/codec/OEM-background result is claimed. Run the acceptance flows on an isolated test target with synthetic data, then an owner-approved account/device trial before real-data release.
2. **Signing and upgrade strategy is now implemented.** The personal0.19.0-update retains app.televault and its installed signer. Public0.19.0 uses app.televault.photos and a new pinned production signing identity; production tasks reject development keys and mismatched certificates. The owner explicitly requested both distributions of the same app. Source/code credentials and signing material are excluded from public source and normal backups. Owner-only signing recovery is separate. Never uninstall/clear data to bypass a mismatch. Source visibility cannot prevent forks or APK reverse engineering; Android signing protects official compatible updates. Telegram client API identity is necessarily extractable from any functioning standalone client; account/session/content/recovery/signing secrets are never embedded.
3. **Security and distribution acceptance.** Native key/grant revocation, fresh-device restore, network/crash transfer recovery, large-media authenticated seeking, ZIP/SAF cancellation, multi-device conflicts/deletion and background scheduling need device/account evidence. Independent crypto/key-lifecycle and dependency security review remain pending. Play distribution additionally needs current permission-policy review for MANAGE_EXTERNAL_STORAGE, foreground transfers and reviewer access, legal/privacy/controller details and store materials. See PLAY_STORE_RELEASE.md.

`./gradlew :app:validateReleaseInputs` checks release inputs without assembling a production APK. `assembleRelease`, `bundleRelease`, `packageRelease`, `validateSigningRelease` and `preReleaseBuild` depend on that gate. No debug-signing fallback exists for release. `assembleHardened` remains the compatible personal-update route; ordinary public UI/version uses `assembleRelease`.

Dynamic cache limits cover disposable ciphertext, not essential catalogs, active staging or deliberate offline downloads. Active readers can temporarily exceed a newly lowered quota until they finish. Android may defer physical cleanup. Vault media remains outside the normal cache. Clipboard clearing is best-effort when Android allows access; app process death prevents a process timer from running. A provider crash between document creation and ownership-proof persistence can leave an unclaimed partial that is preserved to protect unrelated files. These limits are explicit rather than hidden behind a production-ready label.


0.19 native acceptance must also cover restore before auto-backup, changed-name/changed-content/new empty/audio/document cases, explicit force-copy, first-paint snapshot/filter scope, actual metered/Data Saver/device-original bypass, short full warming, long VBR/MKV seek/±30min observed-window pruning/resume, Vault gallery memory cancellation and real per-use CryptoObject enrollment/unlock/cancel/invalidation/account-switch/screen-off. JVM/source/artifact checks cannot exercise Android Keystore or establish exact decoded-time mapping of cached byte blocks. Cache window tags use actual player observations , not sample-accurate extractor timestamps.

Allocation failures in derived flows/index restoration now release RAM caches/partial indexes and retry with cancellation-aware backoff. Encrypted indexes and session/master keys are kept. The optional subject catalog has an8MiB encoded budget; when full it pauses new subject work with a notice and keeps existing search results, without repeated failed serialization or growing the in-memory catalog. This is not an unlimited index or arbitrary-load crash-free guarantee.
