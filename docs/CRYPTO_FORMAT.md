# Additive private cloud format PV2 — 0.18

Normal Photos TVLT1/metadata/root/state event formats are unchanged. Private media nests two TVLT1 authenticated-record streams: independent per-object keys, inner Photos UUID and outer independent Vault UUID, same random object UUID; headers and each record are authenticated before plaintext release. Private file metadata is first sealed with the Photos master under TGDrive/v1/<account>/<photos-vault>/private-vault-v2/<private-vault>/<object>, then with the private master under TGPhotos/private-vault/cloud/v2/<private-vault>/<object>. Public message markers/IDs do not contain filenames or keys. Private manifests use TGDRIVE_V1_FILE:PV2:<photos-vault>:<private-vault>; data uses TGDRIVE_V1_DATA:PV2:<photos-vault>:<private-vault>:<object>:<part-index>; descriptor uses TGDRIVE_V1_PRIVATE_ROOT:<photos-vault>, normal-master authenticated root envelope. No rows in ordinary Photos catalog. Legacy independent Vault descriptor/meta/cipher remain version1 and readable; optional privateKeySalt/privateKeyWrapped/recoveryDisplay extend recovery without removing the original envelope. Fresh private key is an offline recovery secret, not the raw master. Download/export is standard WinZip AES-256 AE-2 ZIP via pinned Zip4j, with generic entry names and encrypted real-name index. See prd/UPDATE_0_18.md for limits and threat boundaries.

# Encryption formats and compatibility — 0.17

## Existing cloud format

The prior VaultCrypto/manifest/chunk/cache/recovery formats and Room schema remain unchanged. Read CRYPTO_AND_BACKUP.md and ARCHITECTURE.md for the original wire/storage definitions. Authenticated records bind vault/object identifiers, index and lengths; manifest commits after uploaded chunks. Existing protected caches persist ciphertext and bounded decrypted pixels/bytes only in memory. Source files outside the Vault remain user's originals, not rewritten. Remote verified restore and owner/Android consent remain required before device removal.

Cloud rename adds an optional displayName to the existing authenticated state event; no raw key, plaintext metadata or mutable file-cipher re-encryption is added. Clients unaware of that event property can still decode the underlying file and see its original immutable manifest name.

## Independent local Private Vault v1

noBackupFilesDir/private-vault-v1 holds descriptor.json and UUID.meta/UUID.cipher. Its master is an independent random 32-byte key, never the cloud master. Each file has an independent random 32-byte key. TVLT1 authenticated records bind this vault UUID and file UUID; exact format is the existing tested VaultCrypto implementation. AES-GCM metadata stores name/MIME/size/date/hash/fileKey, authenticated with TGPhotos/private-vault/metadata/v1/<UUID>. It is sealed under the private master and never put in normal local/cloud search.

Descriptor v1 contains UUID, salts and authenticated master-key wraps; passwords/keys are not plaintext descriptor fields. RecoveryEnvelope uses Argon2id (64 MiB, 3 iterations, 1 lane) with unique 16-byte salts and domain TGPhotos/private-vault/v1/<vaultUUID>. Independently salted offline recovery wrap uses a random 256-bit hex recovery secret. Actual parameters/AEAD nonce generation are defined in core/crypto. Independent Keystore convenience wrap uses DeviceVaultKey with separate account domain -17; enable only after vault unlock and require fresh platform device authentication to use it.

Imports copy/encrypt/fsync and fully authenticate/hash-verify before encrypted metadata is committed. Metadata reads reject invalid hashes/keys/lengths; backup authenticates every file before ciphertext ZIP export. Restore to empty vault validates ZIP paths, limits, pairing and descriptor structure; later password unlock authenticates metadata, and reads authenticate records. Portable backup contains ciphertext and wrapped descriptor, no raw key; password/recovery key is required separately. A recovery key alone cannot restore missing ciphertext after uninstall/data-clear.

Lock/lifecycle/protection changes revoke generation-scoped provider access, close readers and wipe current byte-array keys. Provider is non-exported and grantable only through explicit controlled media operations; Vault external format handling instead exports a user-consented copy so ON_STOP can revoke the live key safely. App previews use memory/seekable authenticated proxy descriptors, not plaintext files. Explicit Save as copy / Open With exports disclose plaintext to the user-selected destination/application. Android/cloud backup of app-private keys/files is disabled.

No automatic hourly key rotation or promise of decrypt immunity after a data-key compromise: stolen valid file keys plus ciphertext can expose that file. Device compromise, captured plaintext and previous exported copies cannot be cryptographically recalled. Offline recovery deliberately retains access. Mandatory primitive tests are not an independent security audit.

## Explicit offline / source retirement (0.18)

Normal-cloud offline pins retain original authenticated TVLT1 ciphertext, with SHA256 scope-derived opaque names and no TTL. The encrypted existing Room envelope stores the account/root scoped pin IDs/hash/length and quota. Every record plus plaintext SHA256 is checked before atomic commit; metadata is committed last. Private Vault entries never enter this store. A server-acknowledged Move-to-Vault retirement uses an encrypted local state-event journal (PREPARED is never replayed as deleted; only REVOKED is), then removes the old normal file-key/job/offline/preview copies. Normal Photos stream formats and per-file keys are not otherwise changed.

## Optional normal-Photos intelligence metadata (0.19.3)

People catalogs/revision snapshots use a distinct `people-v1/<object>` AAD namespace under the unlocked normal Photos master. Optional local OCR text/word-box records use `ocr-v1/<hashed-record-key>`; filenames are SHA-256 source-ID keys, not plaintext names/text. Private-transfer exclusion ledgers/operations use independent `ai-private-v1/<object>` AAD. All include the existing account/vault context and access-epoch guards; ciphertext cannot be substituted between these capabilities. No Private Vault key is supplied to an analysis engine. These new optional metadata namespaces do not change existing file, catalog, recovery or nested Private Vault cipher formats.
